# OverlapSettingsGuard

Version 0.28.0, for Interface 16001. This local addon keeps duplicate features switched off while all addons named in a rule are loaded. `/osg` lists every rule and its current status. It does not enable disabled addons or lock optional appearance choices on.

## Enforcement and scope

Checks run after login, on supported option hooks and every two seconds as a fallback. Changes wait until combat ends. Chat messages explain reverted settings and name any other affected profiles. When a reload is needed, chat asks you to type `/reload` when ready. The guard never opens a popup. Failed enforcement is also reported in chat.

The policy contains 70 rules for the installed pack. Ownership is conditional on addons being loaded, rather than the owner's optional feature currently being enabled; use the owner's settings when choosing whether to automate a task.

CharacterUIBaseline 0.4.0 synchronizes existing owner settings once on each target login/reload, rather than creating a second display or continuous feature toggle, so it adds no rule. Its overlaps are the native Edit Mode active layout (a character on a Blizzard preset is switched once per spec group to the account layout `rex`, followed by an immediate reload; layouts are never imported or edited, and YUI's own "switch to the YUI layout" prompt is disabled), YUI's per-character setup wizard and changelog notice, EllesmereUI's first-install/style pickers and incompatible-add-on popup, GearInsight/MapUtils What's New and Bagnon's outdated popup (all kept from opening at login), GearInsight's leveling window (hidden at load under YUI, matching `gi.levelingstats`, so that rule normally finds it already off), Blizzard's `closedInfoFrames`/`closedInfoFramesAccountWide` and `showTutorials`, chat font/primary-window geometry, EUI `partyUnlockPos`/`unlockPos`, and these display CVars: `nameplateSelectedScale`, `nameplateMaxDistance`, `nameplateMinScale`, `nameplateMaxScale`, `nameplateMaxAlphaDistance`, `nameplateTargetBehindMaxDistance`, `nameplateMinAlpha`, `nameplateMaxAlpha`, `nameplateMinAlphaDistance`, `cooldownViewerEnabled`, `mapFade`, `showQuestLevel`, `cameraSavedPitch`, `cameraSavedDistance` and `enableMultiActionBars`. The source character is excluded and publishes at logout; target edits are reset on the next login. OSG startup preferences still run normally after login and may supersede conflicting captured CVars. EUI spec-to-profile mappings and all specialization/talent data are preserved. `/uib apply` explicitly retries sync; no per-setting lock-off rule is appropriate for this ownership-preserving coordinator.

- GearInsight enforcement targets its current account database, including upstream defaults when fields are absent. Option hooks request a check on the next frame; periodic checks catch database resets and visible frames left behind after failed refreshes. Missing APIs report blocked before storage changes. Friendly-nameplate code lives in the load-on-demand `GearInsight_Forever_Group`, so its absence is normal until that module loads: the setting and the upstream `platesV3` migration marker are written from the main database, and a pending toggle is released by the periodic check once the module exists. The combined resource/cooldown HUD cannot be split with upstream settings, so either relevant owner disables it. The separate rotation recommendation board (`keysBoard`) remains available.
- GearInsight 1.0 to 1.2 switches (`gi.layer*`, `gi.groupautoload`, `gi.questshare`, `gi.magewater`, `gi.lowrank`, `gi.buffask`, `gi.pallyfloat`, `gi.cityplates`, `gi.itemlevel`) are written straight into `GearInsightForeverDB`, where a missing value counts as on. The early ones run when the guard loads, after GearInsight's saved variables exist and before its first layer heartbeat or `PLAYER_LOGIN` setup, so no reload is needed; a missing table is created and GearInsight keeps it. Once GearInsight is running, the guard also leaves its per-map channel (`Layer.SyncPub`), restores nameplates `CityPlates` hid, and refreshes item-level text. `Layer.SetPub`, `CityPlates.SetOn`, `ItemLevel.SetOn`, `LowRank.SetOn`/`SetWhisper`/`SetParty`, `BuffAsk.SetOpt` (when the Group module is loaded at login) and the chat setters are hooked; `/gi layer ...` edits are caught by the periodic check. The layer, quest-share, Mage water, low-rank and buff-request rules have no competing owner: they keep network traffic, automatic whispers and automatic group changes off and pair with YUI as the chat and group owner. GearInsight 1.1.x asks once before auto-accepting, auto-inviting or auto-leaving when those switches are unset; its one-time migration clears only `true`, so the guard's `false` values stay and no prompt appears. GearInsight 1.1.x keeps the leveling window's visibility per character; the guard hides it through `SetLevelingShown(false)`, which it also hooks, at the normal check two seconds after entering the world, so a character that never closed it can show it briefly once.

The lock is checked again after method replacement. A blocked edit explains ownership in chat.

YUI v354 adds `[GearInsight插件]` to its default keywords; the filter stays off.
- YUI's Auction Helper is a YUI component feature. The active profile is switched off through `YUI.Components:SetFeatureEnabled`, whose own callback hides the docked panel and stops its updates at once, so no reload is needed. Stored profiles that have a `Components` table get `AuctionHelper=false`; an unset value counts as on because YUI then uses the feature default. Profiles without a `Components` table are not created. `SetFeatureEnabled` is hooked so switching it back on in YUI's settings is caught on the next frame. A missing feature or API reports a blocked rule and writes nothing.
- EllesmereUI enforcement covers nameplate profiles, spec presets and encoded spec override keys in EllesmereUIDB, using `_ENP_RefreshAllSettings` for the live display. Missing refresh APIs report a blocked rule; failed refreshes are retried. This adapter was verified against shared-suite 9.5.5.
- Forever Essentials enforcement uses each feature's published `Get`/`Cfg`/`Apply` table on `EllesmereUI` (`_SpellUprank`, `_MapReveal`, `_MapFade`, `_JunkItems`, `_ClassicSpellbook`, `_ClassicTalents`, `_MapTravel`, `_ThreatMeter`, `_ZoneLevels`, `_GatherSkill`, `_InGameNavigation`): it sets `enabled=false` (for `euife.skinningskill`, Gathering Skill's `skinning` switch instead) and calls `Apply`, which takes effect without a reload. Each `Apply` is hooked once even when two rules share a feature. `Apply` hooks request a check after an options toggle. Other settings of those features are kept. Fishing and Flight Timer have no installed counterpart and are not guarded. Gathering Skill, Loot Feed, Quest Rewards, Pet Summon, Active Form, Simplified Stats and Macro Manager are off by default and not yet reviewed for overlap. A missing feature API reports a blocked rule and writes nothing.
- MapUtils keeps its namespace private and publishes no refresh API, so enforcement writes its global `MAUTTAB` table. Its settings default to on, so a missing value or missing table counts as on and the table is created if needed. These rules also run when the guard loads, after MapUtils' saved variables exist and before its `PLAYER_LOGIN` setup, so no reload is needed then. A setting turned back on after login is reverted by the periodic check, and chat asks for `/reload`. MapUtils 1.7.x shows piers on zone maps by `WORLDMAPPINS` but on world and continent maps by `WORLDMAPPINS_AZEROTH` (unset counts as on), so `mu.pierpins` writes the category switch `WORLDMAPPINS_ENABLED`, which covers both. MapUtils 1.4.25 also yields its window control by itself once another addon has made the map movable or changed its scale, which YUI does; the rules keep its size grip and settings off as well. YUI's flight marker filter applies the next time the map opens or changes. MapUtils 1.7.15 stops all friend traffic only when both `FRIENDMEMBERSHARE` and `FRIENDMEMBERPINS_ENABLED` are off (`Friends.IsActive`); with either on it greets every online friend at login, so `mu.friendshare` and `mu.friendpins` keep both off, and a source test fails if a new send site or switch check appears. MapUtils 1.8.4's player position on dungeon maps (`INSTANCEPLAYERPOS`) has no rule since 0.27.0: it is kept on by choice, because no other installed addon shows where you are inside a dungeon, although its flight-point super-tracking moves Waypoint UI's pinpoint and arrow while a dungeon map is open. A test checks that no rule writes it.
- Lueur has no rule since 0.17.0: Lueur 2.0.0 removed its minimap herb and ore markers and deletes their `nodeHerbs`/`nodeOre` keys from `LueurDB`, so MapUtils is the only addon marking tracked nodes. The guard no longer writes `LueurDB`; a test checks that the installed Lueur has no node scan. GatherLite's minimap markers show possible spawn locations from its database rather than currently tracked nodes, so they have no rule.
- You Don't Need This 0.6.0 has no rule: it only marks quest items and lists outgrown quests, which no other installed addon does. GearInsight's bag cleanup and junk selling skip quest items, it writes no CVars, and it abandons a quest only after a click and confirmation.
- Skinner enforcement covers the current AceDB profile, its cached active skin profile, stored profiles and the UnitFrames namespace, including inherited defaults. Missing databases or malformed setting paths report blocked before that rule mutates storage. Upstream Skinner files stay unchanged. Addon enablement is recorded separately in each character's AddOns.txt. Player castbar and eight raid-group visibility preferences are saved in the EllesmereUI core profiles; they remain user-adjustable. Layout positions, general HUD content, route/map-pin displays and optional overlapping statistics are not continuously forced by the guard.

## Startup console settings

Two seconds after the first `PLAYER_ENTERING_WORLD` event on each login or UI reload, after the initial overlap checks, the guard makes one separate `SetCVar` call per command, in this order. Each call has the same effect as entering its console command in chat, regardless of the selected addon profile.

```text
/console outlineModeShowLootEffectWhenDisabled 1
/console cameraDistanceMaxZoomFactor 4
/console nameplateMaxDistance 41
/console targetNearestDistanceRadius 50
/console ffxGlow 0
/console volumeFog 0
/console graphicsBloomUserMult 0
/console ResampleAlwaysSharpen 1
/console Contrast 85
/console Brightness 55
/console Gamma 1.5
```

Startup overlaps: YUI's installer and EllesmereUI's camera options also write camera zoom; EllesmereUINameplates writes nameplate distance 60; EllesmereUI's graphics options also write sharpening and its Optimize/Restore actions write contrast. These startup preferences do not disable those addon options or add continuous enforcement rules to `Policy.lua`.

Contrast and brightness use percentage values (85 and 55); gamma uses 1.5.

The values are applied once per session; zone transitions and the two-second overlap checker do not reapply them. Delayed addon initialization or later profile changes can still overwrite them. Startup coverage uses game API stubs; verify the client's accepted values and visible effects in-game. No addon-profile tables or resolution-specific layouts are changed; the same values apply at 1080p, 1440p and 4K. The adoption script already copies these addon files.
Waypoint UI 1.7.4 was reviewed on update: it owns in-world navigation display, while YUI and GearInsight only set the super-tracked destination it displays. No installed addon registers its `/way`, `/waypoint` or `/wp` commands (EllesmereUIQoL, which has an optional `/way`, is absent), so no rule is added. Re-review if TomTom, EllesmereUIQoL or another navigation addon is installed.
Bagnon 12.1.7 was reviewed on install: it owns bag, bank and guild-bank windows. YUI's combined-bag position, `fixBagSortButton` and Profession Assistant backpack entry only act on Blizzard bag frames, which Bagnon no longer shows, so they are inert rather than competing; YUI `bagsBarVisibility="auto"` keeps the Blizzard bag bar hidden. Skinner's Bagnon skin is complementary. No rule is added. Re-review if EllesmereUIBags or another bag addon is installed.
Skinner's EllesmereUI skin has no setting, so a local patch excludes the file rather than a rule; see [AddOns/readme.md](../readme.md). Re-review it and YUI's `EllesmereUIEnhancement` if EllesmereUIBlizzardSkin is installed.

## Maintenance and verification

Add overlapping settings to `Policy.lua` and this table. Extend the relevant adapter and tests when needed; new adapters must be loaded by the TOC and test harness. Verify against installed source when updating addon versions. When an addon is removed, delete its obsolete policies, adapters, TOC dependencies, tests and current documentation.

```powershell
uv run --no-project --with lupa python tools/overlapsettingsguard-tests/run_tests.py
```

The 108 tests use Lua 5.1, game/addon stubs and installed source. They cover policy validation/dependencies, YUI profiles/HUD sets and druid forms, EUI spec overrides, combat deferral, reset detection, runtime refresh failures/retries, GearInsight upstream defaults, visible frames, owner conditions, safe return types and its actual bar-editor code. Skinner coverage includes startup before login, nested settings, stored/namespace profiles, default inheritance, missing owners/databases, reload reporting and real profile resets using its installed AceDB, Core Options and UnitFrames source. MapUtils coverage includes first-run creation, pre-login writes, preserved neighbouring settings, post-login reload requests, YUI flight filters across profiles and a check that every guarded key still exists in installed source. Tests verify preserved planning/wishlists/rotation advice and no action/binding writes through guarded editor methods. They also verify all eleven startup CVars, ordering and once-per-session behavior.

GearInsight 0.5.9 is the verified adapter baseline. Its translated tooltips enrich content rather than replacing YUI/EUI styling. Map destinations and the unique rotation board remain user choices. User-invoked graphics/camera macros can change startup CVars later, just like existing owner options. Layouts are unchanged; actual loading, secret-value handling and rendering at 1080p/1440p/4K still require in-game verification.
