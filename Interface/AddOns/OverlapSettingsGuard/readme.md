# OverlapSettingsGuard

Version 0.13.0, for Interface 16001. This local addon keeps duplicate features switched off while all addons named in a rule are loaded. `/osg` lists every rule and its current status. It does not enable disabled addons or lock optional appearance choices on.

## Enforcement and scope

Checks run after login, on supported option hooks and every two seconds as a fallback. Changes wait until combat ends. Chat messages explain reverted settings and name any other affected profiles. When a reload is needed, chat asks you to type `/reload` when ready. The guard never opens a popup. Failed enforcement is also reported in chat.

The policy contains 50 rules for the installed pack. Ownership is conditional on addons being loaded, rather than the owner's optional feature currently being enabled; use the owner's settings when choosing whether to automate a task.

CharacterUIBaseline 0.2.0 synchronizes existing owner settings once on each target login/reload, rather than creating a second display or continuous feature toggle, so it adds no rule. Its overlaps are native Edit Mode layout (including importing the source layout when different), chat font/primary-window geometry, EUI `partyUnlockPos`/`unlockPos`, and these display CVars: `nameplateSelectedScale`, `nameplateMaxDistance`, `nameplateMinScale`, `nameplateMaxScale`, `nameplateMaxAlphaDistance`, `nameplateTargetBehindMaxDistance`, `nameplateMinAlpha`, `nameplateMaxAlpha`, `nameplateMinAlphaDistance`, `cooldownViewerEnabled`, `mapFade`, `showQuestLevel`, `cameraSavedPitch`, `cameraSavedDistance` and `enableMultiActionBars`. The source character is excluded and publishes at logout; target edits are reset on the next login. OSG startup preferences still run normally after login and may supersede conflicting captured CVars. EUI spec-to-profile mappings and all specialization/talent data are preserved. `/uib apply` explicitly retries sync; no per-setting lock-off rule is appropriate for this ownership-preserving coordinator.

- GearInsight enforcement targets its current account database, including upstream defaults when fields are absent. Option hooks request a check on the next frame; periodic checks catch database resets and visible frames left behind after failed refreshes. Missing APIs report blocked before storage changes. Friendly-nameplate code lives in the load-on-demand `GearInsight_Forever_Group`, so its absence is normal until that module loads: the setting and the upstream `platesV3` migration marker are written from the main database, and a pending toggle is released by the periodic check once the module exists. The combined resource/cooldown HUD cannot be split with upstream settings, so either relevant owner disables it. The separate rotation recommendation board (`keysBoard`) remains available.
- GearInsight 1.0 switches (`gi.layer*`, `gi.groupautoload`, `gi.cityplates`, `gi.itemlevel`) are written straight into `GearInsightForeverDB`, where a missing value counts as on. The early ones run when the guard loads, after GearInsight's saved variables exist and before its first layer heartbeat or `PLAYER_LOGIN` setup, so no reload is needed; a missing table is created and GearInsight keeps it. Once GearInsight is running, the guard also leaves its per-map channel (`Layer.SyncPub`), restores nameplates `CityPlates` hid, and refreshes item-level text. `Layer.SetPub`, `CityPlates.SetOn`, `ItemLevel.SetOn` and the chat setters are hooked; `/gi layer ...` edits are caught by the periodic check. The layer rules have no competing owner: they keep network traffic and automatic group changes off and pair with YUI as the chat and group owner.
- GearInsight has no setting to disable its action-bar editor. The adapter wraps its ten public editing methods (`PlaceMissing`, `Restore`, `AssignSlotKey`, `ApplyKeyTemplate`, `RestoreStolen`, `PlaceSpellAt`, `ClearSlot`, `ClearSpellEverywhere`, `ResetMainBar`, `UnbindKey`) with a conditional runtime lock. A missing method warns once in chat without cancelling the other locks, and a test fails on any unclassified `Keys` function after an update. It preserves caller return types and forwards to the original methods if YUI is not loaded. No protected game APIs or upstream source files are replaced. The lock is checked again after method replacement. A blocked edit explains ownership in chat.
- YUI enforcement covers the active suite profile, stored profiles and stored HUD configuration sets. Resource selections use v351's Forever specialization catalog, including druid forms and the resource manager's `itemsByContext`, which edited contexts read instead of `bySpec`; swing timers and custom resources are untouched. Player health and cast resources are opt-in upstream, so missing selections do not trigger a change. Dedicated cast-only groups bypass selections and are separately disabled; native castbar suppression stays off. Nameplate runtime Disable methods restore/stop their behavior, and YHUD's configuration-change API rebuilds its active display. Missing APIs block enforcement before storage changes. Failed HUD refreshes remain pending per rule for retry.
- Chat rules: YUI v352 added a YChat keyword filter that hides player messages containing `[GearInsight 无限版]` or `白云飞整合插件任务指南`, on by default; GearInsight 0.5.11 re-enabled its guild/officer level prefix. Both are chat-message filters, so they are kept off whenever both addons load. The YChat change goes through `YChat:SetMessageFilterEnabled` for the active profile and writes `messageFilter.enabled=false` into stored profiles that have a YChat table; a missing filter table counts as on because YChat normalizes it that way. GearInsight's prefixes are switched off with `GuildChatLevel.SetEnabled(false)`, `SetWhisperOn(false)` and `SetPartyOn(false)` (whisper and party prefixes since 1.0); its filters read the flags per message, so no reload is needed. All setters are hooked, and the periodic check catches direct edits. GearInsight's own level-up filter (`/gi 屏蔽升级`) is not guarded; since GearInsight 0.7.x it is off by default (`/gi 屏蔽升级 开` turns it on). YUI v354 adds `[GearInsight插件]` to its default keywords; the filter stays off.
- YUI's Auction Helper is a YUI component feature. The active profile is switched off through `YUI.Components:SetFeatureEnabled`, whose own callback hides the docked panel and stops its updates at once, so no reload is needed. Stored profiles that have a `Components` table get `AuctionHelper=false`; an unset value counts as on because YUI then uses the feature default. Profiles without a `Components` table are not created. `SetFeatureEnabled` is hooked so switching it back on in YUI's settings is caught on the next frame. A missing feature or API reports a blocked rule and writes nothing.
- EllesmereUI enforcement covers nameplate profiles, spec presets and encoded spec override keys in EllesmereUIDB, using `_ENP_RefreshAllSettings` for the live display. Missing refresh APIs report a blocked rule; failed refreshes are retried. This adapter was verified against shared-suite 9.5.5.
- Forever Essentials enforcement uses each feature's published `Get`/`Cfg`/`Apply` table on `EllesmereUI` (`_SpellUprank`, `_MapReveal`, `_MapFade`, `_JunkItems`, `_ClassicSpellbook`, `_ClassicTalents`, `_MapTravel`, `_ThreatMeter`, `_ZoneLevels`): it sets `enabled=false` and calls `Apply`, which takes effect without a reload. `Apply` hooks request a check after an options toggle. Other settings of those features are kept. Fishing and Flight Timer have no installed counterpart and are not guarded. Gathering Skill, Loot Feed, Quest Rewards, Pet Summon, Active Form, Simplified Stats and Macro Manager are off by default and not yet reviewed for overlap. A missing feature API reports a blocked rule and writes nothing.
- MapUtils keeps its namespace private and publishes no refresh API, so enforcement writes its global `MAUTTAB` table. Its settings default to on, so a missing value or missing table counts as on and the table is created if needed. These rules also run when the guard loads, after MapUtils' saved variables exist and before its `PLAYER_LOGIN` setup, so no reload is needed then. A setting turned back on after login is reverted by the periodic check, and chat asks for `/reload`. MapUtils 1.4.25 also yields its window control by itself once another addon has made the map movable or changed its scale, which YUI does; the rules keep its size grip and settings off as well. YUI's flight marker filter applies the next time the map opens or changes.
- Lueur also keeps its namespace private, so enforcement writes `nodeHerbs` and `nodeOre` in its global `LueurDB` table, where a missing value counts as on. Lueur 1.6.0 and later default both markers to off, so the rules only matter when someone switches a marker on. Written before login, this needs no reload; a marker switched back on later is reverted with a request to `/reload`. GatherLite's minimap markers show possible spawn locations from its database rather than currently tracked nodes, so they have no rule.
- Skinner enforcement covers the current AceDB profile, its cached active skin profile, stored profiles and the UnitFrames namespace, including inherited defaults. Skinner-only checks also run when the guard loads and at `PLAYER_LOGIN`, before Skinner's delayed skin passes; profile reset/copy/change callbacks and periodic checks catch later edits. Already applied skins require `/reload` because changing settings cannot undo their texture and hook changes. Missing databases or malformed setting paths report blocked before that rule mutates storage. Upstream Skinner files stay unchanged. Blizzard-window and Auctionator skinning remain available; no layout, UI-scale or viewport setting is imposed.

Addon enablement is recorded separately in each character's AddOns.txt. Player castbar and eight raid-group visibility preferences are saved in the EllesmereUI core profiles; they remain user-adjustable. Layout positions, general HUD content, route/map-pin displays and optional overlapping statistics are not continuously forced by the guard.

## Startup console settings

Two seconds after the first `PLAYER_ENTERING_WORLD` event on each login or UI reload, after the initial overlap checks, the guard makes one separate `SetCVar` call per command, in this order. Each call has the same effect as entering its console command in chat, regardless of the selected addon profile.

```text
/console outlineModeShowLootEffectWhenDisabled 1
/console cameraDistanceMaxZoomFactor 4
/console nameplateMaxDistance 41
/console targetNearestDistanceRadius 50
/console ffxGlow 0
/console volumeFog 0
/console graphicsBloomUserMult 0
/console ResampleAlwaysSharpen 1
/console Contrast 85
/console Brightness 55
/console Gamma 1.5
```

Startup overlaps: YUI's installer and EllesmereUI's camera options also write camera zoom; EllesmereUINameplates writes nameplate distance 60; EllesmereUI's graphics options also write sharpening and its Optimize/Restore actions write contrast. These startup preferences do not disable those addon options or add continuous enforcement rules to `Policy.lua`.

Contrast and brightness use percentage values (85 and 55); gamma uses 1.5.

The values are applied once per session; zone transitions and the two-second overlap checker do not reapply them. Delayed addon initialization or later profile changes can still overwrite them. Startup coverage uses game API stubs; verify the client's accepted values and visible effects in-game. No addon-profile tables or resolution-specific layouts are changed; the same values apply at 1080p, 1440p and 4K. The adoption script already copies these addon files.
Waypoint UI 1.7.4 was reviewed on update: it owns in-world navigation display, while YUI and GearInsight only set the super-tracked destination it displays. No installed addon registers its `/way`, `/waypoint` or `/wp` commands (EllesmereUIQoL, which has an optional `/way`, is absent), so no rule is added. Re-review if TomTom, EllesmereUIQoL or another navigation addon is installed.
Bagnon 12.1.7 was reviewed on install: it owns bag, bank and guild-bank windows. YUI's combined-bag position, `fixBagSortButton` and Profession Assistant backpack entry only act on Blizzard bag frames, which Bagnon no longer shows, so they are inert rather than competing; YUI `bagsBarVisibility="auto"` keeps the Blizzard bag bar hidden. Skinner's Bagnon skin is complementary. No rule is added. Re-review if EllesmereUIBags or another bag addon is installed.
Skinner's EllesmereUI skin has no setting, so a local patch excludes the file rather than a rule; see [AddOns/readme.md](../readme.md). Re-review it and YUI's `EllesmereUIEnhancement` if EllesmereUIBlizzardSkin is installed.

## Maintenance and verification

Add overlapping settings to `Policy.lua` and this table. Extend the relevant adapter and tests when needed; new adapters must be loaded by the TOC and test harness. Verify against installed source when updating addon versions. When an addon is removed, delete its obsolete policies, adapters, TOC dependencies, tests and current documentation.

```powershell
uv run --no-project --with lupa python tools/overlapsettingsguard-tests/run_tests.py
```

The 65 tests use Lua 5.1, game/addon stubs and installed source. They cover policy validation/dependencies, YUI profiles/HUD sets and druid forms, EUI spec overrides, combat deferral, reset detection, runtime refresh failures/retries, GearInsight upstream defaults, visible frames, owner conditions, safe return types and its actual bar-editor code. Skinner coverage includes startup before login, nested settings, stored/namespace profiles, default inheritance, missing owners/databases, reload reporting and real profile resets using its installed AceDB, Core Options and UnitFrames source. MapUtils coverage includes first-run creation, pre-login writes, preserved neighbouring settings, post-login reload requests, YUI flight filters across profiles and a check that every guarded key still exists in installed source. Tests verify preserved planning/wishlists/rotation advice and no action/binding writes through guarded editor methods. They also verify all eleven startup CVars, ordering and once-per-session behavior.

GearInsight 0.5.9 is the verified adapter baseline. Its translated tooltips enrich content rather than replacing YUI/EUI styling. Map destinations and the unique rotation board remain user choices. User-invoked graphics/camera macros can change startup CVars later, just like existing owner options. Layouts are unchanged; actual loading, secret-value handling and rendering at 1080p/1440p/4K still require in-game verification.
