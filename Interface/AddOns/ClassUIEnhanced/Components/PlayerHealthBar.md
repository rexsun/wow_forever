# PlayerHealthBar

DF health bar. Configurable bar texture (LSM), bar color (class color or health-gradient via `C_CurveUtil.CreateColorCurve` evaluated against `healCalculator:EvaluateCurrentHealthPercent`), and text display (percentage, current health, or both). Health gradient uses a linear color curve with three configurable color points (low at 0%, mid at 50%, full at 100%) from `private.profile.health_gradient_colors` to produce secret color values compatible with `SetStatusBarColor` (AllowedWhenTainted). Gradient colors are editable from the Options panel; the curve cache invalidates on change.

Shield absorption overlay and incoming heal prediction overlay are toggleable via `show_shields` and `show_healing_prediction` (both enabled by default); toggling forces a unit re-registration so the framework updates event subscriptions. DF re-registers only on a unit change, and its `SetUnit(nil)` also `Hide()`s the bar, so `Refresh` restores the bar's shown state around it: the Options setter runs no layout pass, and the toggle used to hide a visible bar until the next one. Value text positioned via `ApplyFontProfile` using `value_font` anchor_point/offsets. Below SecondaryResources (**disabled by default**).

`interactable` adds a `SecureUnitButtonTemplate` click overlay (player menu). It is parented to UIParent and pinned to the bar's screen coordinates, never anchored to it, because anchoring would make the bar implicitly protected. Both corners are pinned to the bar's rect, so the click area is the bar's real size, including a width that comes from its anchor. It used to be sized from the profile's width and height, which did not match such a bar. `ContentLayout` re-places it after each layout pass has positioned the bar; `Refresh` runs before that pass and sees the old rect. It is shown only while the bar is shown and has a rect, and it never moves in combat. Hiding the bar does not hide it, so an `OnHide` hook does; a secure button cannot be hidden in combat, so an `OnLeaveCombat` listener hides it if the bar went mid-fight. Without them, a pass that hid the bar (a mount, combat ending under an `out_of_combat` hide) left an invisible click area behind.

`Refresh` binds and styles the bar whenever the component is enabled, whatever its visibility: the layout pass owns `Show`/`Hide`, and DF's bar never shows itself. It used to gate on `IsVisibleForComponent`, so a bar hidden by its mode or a rule was unbound (`SetUnit(nil)`) and skipped every setting edited meanwhile — and the passes that reveal it (the pull, a dismount) call `ContentLayout`, never `Refresh`, so it came back with frozen health and stale styling.

Defaults: 200×20.
