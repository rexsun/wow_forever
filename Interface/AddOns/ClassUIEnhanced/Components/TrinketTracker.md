# TrinketTracker

Standalone (no CooldownViewer). Equipped on-use trinkets (`C_Item.GetItemSpell` non-nil) and proc trinkets (see below). Horizontal/vertical layout. Dynamic icon limit (2 in Edit Mode, `reserve_slots`, or actual count). Glow on cooldown finish. Right of CooldownTracker. `GetWantsContentWidth()` → true. `duration_font` profile with anchor_point/offsets controls active buff duration text positioning via `ApplyFontProfile`. Hover tooltip via `private.Tooltip.Apply` (`SetInventoryItem("player", slotID)`); `tooltip_mode` default `off`.

Defaults: icon_size 50.

**Proc trinkets:** Equipped trinkets with no on-use spell but a `private.TrinketData.proc[itemID]` entry are displayed too. They have no inventory cooldown, so tracking is event-driven: `rebuildProcIndex` (called from `refreshAllIcons`) maps each proc buff `spellID` → slot, and `SPELL_UPDATE_COOLDOWN` routes to `onProcFired`. On fire it records the firing `spellID` (`icon.procSpellID`), stamps the active-window timer for the longest buff (`durs[1]`), and — for the `stack` buff — counts repeated procs within the buff window (`StackText`, shown at ≥2 stacks). A per-`spellID` wall-clock debounce (`PROC_DEDUP_WINDOW`, 0.1s) drops same-frame double-fires — `startTime` can't be compared because it is secret. The ICD is **not** stored as raw numbers: `C_Spell.GetSpellCooldown(procSpellID)`'s `startTime`/`duration` are secret in 12.0+ and comparing them taints. Instead `onUpdate` polls only the non-secret `isActive`/`isOnGCD` booleans for the greyed state and renders the sweep once on the off→on transition via `SetCooldownFromDurationObject(C_Spell.GetSpellCooldownDuration(procSpellID))`. Idle (off ICD) = bright. Proc runtime state is reset only on an actual item swap (`icon.procItemID` guard) so the live window survives the `BAG_UPDATE_COOLDOWN` refresh path. On-use buff durations also prefer `TrinketData.onUse[itemID]` over `ParseItemBuffDuration`. `getActiveTrinketCount` counts proc trinkets so they occupy a layout slot and don't collapse the chain.

**Stacks trinkets:** a `private.TrinketData.stacks[itemID] = spellID` trinket has no window to time, only a stacking aura on the player. Wavecaller's Seastone ramps Tidal Insight (1295057) to 6 and back down, and the aura is permanent. It shows like a proc trinket (`isProc`, `procData = nil`, never greyed, since there is no ICD), and its readout is the aura's stack count. That count is secret in combat, so it is **bound, not read**: `syncStackTap` gives each trinket slot an `AuraContainer` whose one `HELPFUL` slot is filtered to that spell, and binds a FontString via `SetApplicationCount`. Blizzard writes the count into it engine-side, and its default formatter leaves 0 and 1 blank, matching the proc `StackText` rule of 2 or more. Three constraints shape it:
- **The container is on `UIParent`, never under `trinketContainer`.** An aura container makes its ancestors protected in combat, and `applyLayout` resizes `trinketContainer` in combat on purpose.
- **So the text does not inherit the icon's visibility.** The FS is created on the slot button (the bind rejects any other parent) and reaches the icon by a cross-frame anchor. `syncStackTapAlpha` mirrors the icon onto the container's alpha from the icon's `OnShow`/`OnHide` hooks (which also fire for an ancestor), from every `refreshAllIcons`, and from the 0.2 s poll for fades. A routed icon that ignores parent alpha contributes its own alpha.
- **Creation, the anchor and the strata/level sync wait for a writable pass** (out of combat *and* auras not secret). Re-filtering is legal at any time but deduped, because every call ends in `UpdateAllAuras`. Nothing is lost by waiting: trinkets cannot be swapped in combat.

Pinned by `tests/trinketstacks_check.lua`. **Not yet run in a client.**

**`show_passive` (default on):** Governs whether proc trinkets appear at all; orthogonal to `reserve_slots`, which only governs whether a vacated slot's space collapses or is held. When off, `refreshTrinketIcon` routes the proc icon into the placeholder/hide branch (Edit Mode shows its real icon for positioning; normal mode hides it), `getActiveTrinketCount` stops counting it (so the frame collapses with Reserve off, stays 2-wide with Reserve on), and `rebuildProcIndex` early-returns so no `SPELL_UPDATE_COOLDOWN` proc tracking runs while hidden.

Trinkets whose only equip effect is a damage/summon proc (no buff aura with a duration) are intentionally not tracked — they are listed, commented, in the per-channel `Core/TrinketData/<channel>.lua`. `private.TrinketData` is the dataset chosen by the in-game version gate in `Core/TrinketData.lua` (the flavor whose TOC interface best matches the client), so the consumer code here is flavor-agnostic. The DBs are generated offline; see `ItemInfoDB/README.md`.

**Timer smoothness:** `onUpdate` runs two throttles. The cooldown/glow poll stays at `UPDATE_INTERVAL` (0.2s); the active-buff readout ticks separately at `TEXT_INTERVAL` (0.1s), matching its tenth-of-a-second display granularity. Both accumulators subtract their interval rather than zeroing — zeroing discards the frame overshoot, so the real period drifts by a frame per tick and the displayed tenths skip. The engine countdown is protected by `setIconCooldown` (`Util.SetIconCooldown`, shared with ConsumableTracker; called with no timing it clears), which caches the applied `start`/`duration` on the icon and no-ops when unchanged: re-issuing `SetCooldown` with identical values restarts the engine's countdown, and both the 0.2s poll and the `SPELL_UPDATE_COOLDOWN`/`BAG_UPDATE_COOLDOWN` refresh path used to do exactly that, making the shown seconds jump and stagger.

**Additional frame routing:** Individual trinket slots (13, 14) can be assigned to additional frames via the spell dropdown (source key `"Trinket"`). Routed icons are positioned by AdditionalFrameManager via cross-parent `SetPoint` + `SetIgnoreParentAlpha(true)`. TrinketTracker continues updating data/glow/cooldown for routed icons; `applyLayout` skips positioning them. The container is sized for `getEffectiveIconLimit() - getRoutedSlotCount()`, and the routed count only includes slots the limit counted: every slot in Edit Mode or with `reserve_slots`, otherwise only active ones (`isSlotActive`). A routed slot that was also excluded or empty used to be subtracted twice, which drove the limit to 0 and collapsed the container under live icons. When disabled but has routed icons, the container stays shown at alpha 0 so OnUpdate keeps running. `GetIconFrame(slotID)` exposes icon frames for the AF manager. Notifies AF via `OnAddonIconRefresh()` after each refresh.

**Fonts:** applied only while shown, so a font edit made while hidden goes on a `fontsOwed` latch that the next shown `Refresh` consumes; the layout pass that reveals the tracker (a target gained, a dismount, the pull under an `out_of_combat` hide) carries no font pass. `RacialTracker` and `ConsumableTracker` do the same.

**Free-moving Frame Point:** `syncFramePointToAlignment` re-derives `frame_point` from `layout_alignment` on every layout pass, so the alignment edge stays fixed as the container resizes. A Frame Point the user picked by hand (`anchor_profile.frame_point_manual`) wins, and an Edit Mode drag clears the mark (`Core/UI/README.md`, EditMode).

**CDM alert replay:** the `onUpdate` poll publishes its on/off-cooldown edge to
`private.CDMAlerts.OnEquipSlotCooldownChanged(slotID, isOnCooldown, icon)`, so a Sound / TTS /
Visual alert the player configured against that trinket in Blizzard's Cooldown Manager plays
here. The slot is the key: this component reads the equipped item straight off inventory slot
13/14 and holds no cooldownID, and CDMAlerts keeps the `equipSlot -> resolvedKey` index for
exactly that. It covers the common arrangement too — a trinket the player has *not* dragged into
Essential/Utility sits in an item category that no CooldownViewer renders, so Blizzard's own
alert clock never runs for it and these icons are the only place it can play. See
`Core/CDMAlerts.md`, "Item categories and the trinket bridge".

An equip change on slot 13/14 is a fresh bind: `PLAYER_EQUIPMENT_CHANGED` calls
`CDMAlerts.ReleaseButton` on that slot's icon before refreshing, which drops the old item's
cooldown edge and any running visual alert. Without it, swapping an on-cooldown trinket for a
ready one fired the new trinket's "Available" alert on equip.
