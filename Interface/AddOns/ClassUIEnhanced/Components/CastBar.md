# CastBar (shared module)

Shared by PlayerCastBar, TargetCastBar, FocusCastBar. Frame: `containerFrame` → `Icon` + `StatusBar`. Channel tick marks (2×height sparks) from `ticksByName`/`ticksById`, rebuilt on `PLAYER_TALENT_UPDATE`. The tick hook skips a hide while `channeling` is set, because a clipped channel's stale `CHANNEL_STOP` arrives after the new `CHANNEL_START`. `EMPOWER_START` is exempt: DF routes it through `CHANNEL_START` before the hook runs, so `channeling` is always set for it, and an empower replaces a channel's ticks. `ApplyTexture`/`ApplyFonts` (uses `ApplyFontProfile` for cast name and cast time text positioning). `CreateCastBarComponent(unitId, name)` factory.

**Cast time style** (`cast_time_style`, all three cast bars): `"remaining"` (default, DF's plain countdown), `"elapsed_total"` or `"remaining_total"` — the latter two render as `1.2 / 2.5`, with the total taken from `spellEndTime - spellStartTime`. `setupCastBarStyling` replaces the bar's own `OnTick_LazyTick` with a copy that routes through `castBar.FormatCastTime`; the instance method table is per-bar (DF Mixin), so no shared framework function is touched, and `installCastTextTrace` still wraps whatever is installed. `ApplyFonts` mirrors the setting onto `bar.cueTimeStyle`, so its setters must raise `private.fontsDirty`. `FormatCastTime` falls back to remaining-only when either value is secret or the total is unknown — arithmetic over a secret throws inside the OnUpdate, where the error would be invisible. The PlayerCastBar instant-cast GCD overlay and the Edit Mode preview (a dummy 1.5 s of 3.0 s cast) use the same formatter.

**Mass Disintegrate glow**: optional pulsing border on the cast bar when channeling Disintegrate with Mass Disintegrate charges active (Scalecommander Evoker); controlled by `mass_disintegrate_glow` profile key on PlayerCastBar.

**Spell pushback**: when the player is damaged mid-cast the client pushes the cast back (on WoW Forever a hard cast's whole window shifts later, start and end both, verified in a client; a channel loses time off the end instead). Two halves, both in the `SetTimerDuration` shim: the timing correction and the cutaway.

- **Timing — the fill is bound from cast info (#50; unverified in a client).** `unitframe_midnight.lua` is the cast bar implementation on 12.1.0, 12.1.5 and Forever alike (`fw.lua:269` — `IsMidnightWowAPI()` covers `[11509,20000)` as well as `[120000,130000)`), so there is nothing to branch on. DF binds the fill from the duration getters: `UnitCastingDuration` at cast start and on `UNIT_SPELLCAST_DELAYED` (`:1650`, `:2151`), `UnitChannelDuration` in `UpdateChannelInfo` (`:1868`), which `UNIT_SPELLCAST_CHANNEL_UPDATE` runs. Blizzard's own cast bar, which #50 reports as following a pushback, recomputes from `UnitCastingInfo`/`UnitChannelInfo` start and end (`CastingBarFrame.lua:494`/`:524`) and reads no getter. The fill is engine-driven from the binding, so the reported symptom — the bar filling at the pre-pushback rate — means a stale binding, and the getter is the one input the two bars do not share. So the `SetTimerDuration` shim (see the guard below) binds `castBar.CastInfoDuration(bar)` in place of DF's object on every bind where that info is readable: a `DurationObject` spanning `UnitCastingInfo`/`UnitChannelInfo` start to end (a new `C_DurationUtil.CreateDuration()` per bind, then `SetTimeSpan(startMs / 1000, endMs / 1000)`; a mutated object re-bound is not known to take effect). It stores it as `durationObject`, which the time text, the tick marks and DF's stop handlers read, and passes DF's interpolation and direction through. **One writer.** Every DF bind reaches the shim, including the `PLAYER_ENTERING_WORLD` re-read each component `Refresh` runs mid-cast. That re-read calls DF's methods directly and runs no hooks, so a re-bind in the pushback `OnEvent` hook would have been overwritten by the stale getter the next time anything refreshed. The shim applies at cast start too, where the two sources should agree, so the player bar fills exactly as Blizzard's does. Cast info is plain for the player and their pet and secret for other units (`SecretWhenUnitSpellCastRestricted`; a per-spell flag can override either way), so target/focus normally keep DF's object. An empowered channel always does, since its span includes the hold time (`UnitEmpoweredChannelDuration`); that is read from `UnitChannelInfo`'s own `isEmpowered` (`NeverSecret`), because DF sets `bar.empowered` for the `"player"` token only (`:1812`). **Channel tick marks follow suit:** a pushed-back channel keeps its tick interval and loses its last ticks, so on `UNIT_SPELLCAST_CHANNEL_UPDATE` `UpdateCastTicks(bar, keepInterval)` keeps the interval measured when that spell's channel started and hides marks past the new end. It used to space them evenly over whatever the bar spans. The Evoker path keeps its own baseline logic. **Not covered:** DF dropping `UNIT_SPELLCAST_DELAYED` on a hidden bar (`IsValid`, `:1185`), since its setter is never reached. A player bar is hidden mid-cast only by a component disable (`castBar.HideForUnit`): PlayerCastBar's `Refresh` calls `HideEditModePreview` only while not casting. TargetCastBar/FocusCastBar's call it on every non-Edit-Mode `Refresh`, but a visible pass then re-reads the cast through `PLAYER_ENTERING_WORLD`, which binds through the shim. **The cause is inferred, not observed:** `UnitCastingDuration` is `SecretReturns`, so no addon read can show whether it missed the pushback. What a client run can show is whether the fix works (trace below).
- **Pushback trace.** `installCastTextTrace` wraps both DF pushback handlers (instance-local, like the lazy-tick wrap) and, under `/cue debugcast`, logs a `Pushback` line sampled *before and after* DF's handler: `casting`/`channeling`/`empowered`, `castBarID`, `IsShown()` (the hidden-bar tell), `delayTimeMs` from the 11th `UnitCastingInfo` return, and `maxValue` / `spellEndTime` / remaining duration as `before -> after`. A handler that runs but moves nothing is the diagnostic case, and only a before/after pair shows it. Every duration and timestamp goes through `describeValue` / `describeDuration` — all of them can be secret. After DF's handler it also logs `bound`, the remaining time of the bar's actual engine binding (`StatusBar:GetTimerDuration()`, which nothing else reads). With the #50 fix, a player cast's `remaining` should grow across the line by about the pushback, and `bound` should match it. A `bound` that disagrees means something bound the bar outside the shim.
- **Nil-duration guard (applied unconditionally, on the setter).** All three duration getters DF feeds into `SetTimerDuration` are `MayReturnNothing` — `UnitCastingDuration`, `UnitChannelDuration`, `UnitEmpoweredChannelDuration` — while the setter's `duration` is `Nilable = false`, and DF hands each straight across at all three live call sites (`:1650` cast start, `:1868` channel/empower, `:2151` pushback; `:2175` sits below `CHANNEL_UPDATE`'s `if true then return end` at `:2156` and never runs). An empty return throws inside DF's `eventFunc` (`:1424`), *before* `RunHooksForWidget` (`:1425`), so that dispatch's CUE `OnEvent` hooks (tick marks, the latency-marker re-derive) are skipped. **An ended cast is not how that happens:** DF reads `name` from `UnitCastingInfo` first and `IsValid` returns false on `not castName` (`:1196`) before the setter is reached, so the throw needs `name` non-nil *and* the getter empty — the two reads of one cast disagreeing. Narrow, and unproven in a client. `setupCastBarStyling` therefore guards the **setter**, not the handlers: `SetTimerDuration` is the raw widget method (nothing in DF defines one), so an instance field shadows the metatable lookup for that bar alone, covering cast, channel and empower from one place, re-calling no getter DF has already called this dispatch, and leaving DF's `spellStartTime`/`spellEndTime`/`maxValue` writes intact — only the engine binding is skipped, and the bar keeps its previous one. Since #50 the shim binds the cast-info span first whenever it is readable, so a skip needs the getter *and* the info to be empty. DF also stores the nil as `self.durationObject` before the setter runs, so CUE's `OnTick_LazyTick` replacement blanks the time text rather than dereferencing it; without that check it would throw on every frame for the rest of the cast, since DF resets `lazyUpdateCooldown` only after the tick returns (`:1478`). A nil test touches nothing secret: a DurationObject is an opaque handle, not a secret (`patterns-secrets.md`). Under `/cue debugcast` a suppressed bind logs a `NilDuration` line, which is the D2 tell — now only where cast info is unreadable (target/focus), since the player bar binds the span first (the pushback trace does not sample it a second time).
- **Cutaway (`pushback_flash`, PlayerCastBar only, default on).** On a pushback the fill drops back at once, and the progress it lost stays drawn as a solid red block (`CUTAWAY_COLOR`, full alpha, normal blend) that holds for 0.15 s and fades over 0.4 s. It replaced a white `ADD` flash over the whole bar (0.3 s, peak alpha 0.7), which the user found too faint: additive white barely moves an already-bright fill, while the lost block mostly sits over the dark background. The profile key keeps the flash's name, so no migration. **Decided in the shim**, the one place that sees the span a bar had (`cueSpanKey`/`cueSpanEnd`, stored per bind) and the span it gets. The block is drawn when the new span belongs to the **same cast** (castID for a cast; a channel has none, so its `castBarID`) and the fill dropped: `castBar.LostSpan` measures the old fill against the **old** span and the new fill against the new one, and returns `[new, old]`. Both starts matter: WoW Forever shifts a pushed-back cast's whole window (start and end both `+delayTimeMs`, `.context/api.md`), so a first cut that measured both from the new start drew a sliver or nothing — the in-client report "the pushback does not always show". Anything else returns nil: the next cast (a new key), a same-span re-read (Refresh), a channel *extended* (the flash used to fire on those too), and a loss under 0.5% of the bar. The bind then uses `Immediate` interpolation instead of DF's `ExponentialEaseOut`, so the fill does not slide over the block. `castBar.ShowPushbackCutaway` anchors a lazily created texture from the left (bottom, on a vertical bar) at `width × low` to `width × high`; a second pushback during the fade replaces the block. Drawn at **ARTWORK sublevel 2**: above DF's fill (ARTWORK -6) and the latency overlay (ARTWORK 1), below everything DF puts in OVERLAY, so the spell name (1), spark (3), icon (4) and time text (7) stay readable over a solid block. DF's finish flash (OVERLAY 7, `:2252`) is not reused: DF plays it on finish and interrupt and hides it on every re-setup. Player only, like the rest of the correction: other units' cast info is secret, and target/focus carry no key. Empowered channels keep DF's binding and get no cutaway. The setting is read live per bind, so it is not a restyle-applied key and its setter must not raise `private.fontsDirty`. There is **no client-version gate**: pushback from damage is a classic-era mechanic, so one path gives classic the behaviour and modern content nothing. Teardown (stop + hide) runs on `OnCastStart` (back-to-back casts never re-`Hide()` the bar), on a `HookScript("OnHide")` (DF's `OnHide` does not call `RunHooksForWidget`), and in `HideEditModePreview`, since `Animation_StopAllAnimations` only knows DF's own hubs. **Verified in a client:** the cast shift and the castID key (debug log, 2026-09-27). **Unverified:** channel pushback on any client, and the look after the geometry fix. The `castdebug Cutaway` line under `/cue debugcast` logs every input of the decision (same cast, start and end before and after, now, setting, lost span).
- Regression cover: `tests/pushback_check.lua` drives `castBar.LostSpan` over a cast and a channel pushback, the no-loss directions, a sliver and a degenerate span, and the shim's cutaway decision: the first bind, a pushback (block plus `Immediate`), a same-span re-read, the next cast, the setting off, and a channel cut short versus extended. It also installs the extracted shim and `CastInfoDuration` on test bars and drives DF-style binds through them: the cast-info span for a cast and a channel, pass-through of DF's interpolation and direction, a new object per bind across a pushback, a later stale-getter bind that must not undo it, the cases that keep DF's object (empowered by DF's flag or by `UnitChannelInfo` on a non-player bar, secret info, ended cast, no cast state, no unit), and the nil-duration skip with its `NilDuration` line. `UpdateCastTicks` is driven over a channel start, a pushback to a shorter span (interval kept, lost ticks hidden) and the next start.

**Cast text tracing (`/cue debugcast`)**: toggles diagnostics for "cast time text not visible" reports; writes to the debug log (read with `/cue log`). Each toggle also logs a one-shot snapshot of every bar. The cast time text is written *only* by the addon's `OnTick_LazyTick` replacement (see **Cast time style**; it mirrors DF's original at `unitframe_midnight.lua:1429`), which requires `Settings.CanTick` (installs the OnUpdate), `Settings.CanLazyTick` and `Settings.ShowCastTime` to all be true, and reads `durationObject:GetRemainingDuration()` — a secret whenever the bar holds DF's getter object rather than the #50 cast-info span, so the trace guards every duration and `GetText()` read with `issecretvalue`. `installCastTextTrace` wraps the bar's own `OnTick_LazyTick` (Mixin copies `CastFrameFunctions` per bar, so the wrap is instance-local) and adds an `OnCastStart` hook; both early-return on a boolean when tracing is off.

The lazy tick is only *reached* if DF's `OnTick` (line 1470) sees `OnTick_Casting` / `OnTick_Channeling` survive `CheckCastIsDone` (line 1219), whose `self.value >= self.maxValue` test compares absolute millisecond timestamps and is skipped entirely when those are secret. Under 12.0 `self.value` is the cast **start** and is not updated per tick (the fill is native, driven by `SetTimerDuration`), so the test stays start-vs-end, never trips on a healthy bar, and `UNIT_SPELLCAST_STOP` is what actually ends the cast. Degenerate values — equal, zeroed, or a `maxValue` left over from a previous cast — declare it finished on every tick and the text is never written, while the bar itself still animates. Both phase functions are wrapped (`TickCasting` / `TickChanneling` log lines) to report `value`, `maxValue`, the `alive` return and a running `lazyTicks` count, sampled *before* the call since `CheckCastIsDone` fires `UNIT_SPELLCAST_STOP` on its way out. The lazy tick itself is called directly — a throw inside DF propagates rather than being caught and logged. Per-frame lines are throttled to transitions plus twice a second.
