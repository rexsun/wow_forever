# ConsumableBuffTracker

Standalone. Status icons for long-duration consumable buffs: flasks, food (Well Fed), augment runes, weapon oils, weapon stones/buffs, and (every classic client) shaman weapon imbues and rogue poisons. Each category shows a single icon with remaining duration or a desaturated "missing" state with glow to indicate the buff is not active. Click-to-use via SecureActionButton.

**Detection methods:** Aura-based categories (flask, food, rune) are detected via player aura scanning. Weapon enchant categories (oil, weapon buff) use `C_PaperDollInfo.GetTemporaryEnchantmentInfo(slot)` per weapon slot to detect temporary weapon enhancements; the imbue and poison categories read Forever's `C_Item.GetWeaponEnchantInfo` (below).

**Per game client (#27).** `BUFF_CATEGORIES` and `BUFF_ENTRIES` are picked at load by `private.ClientScope.CLIENT` from a retail, Forever, Era, TBC, Wrath or MoP table (Era shares Forever's entries), and `CATEGORY_ORDER` follows the client's own categories, so the Options panel lists only what exists there. IDs from each client's DB2 (1.60.1.70245, 1.15.9.70003, 2.5.6.69795, 3.80.2.70177, 5.5.4.70032); flask and food entries are the buff auras, not the alchemy and cooking spells. A flask's buff is its item's use spell (Wrath's Flask of the North picks one of three, `67016`–`67018`); a food's is the spell its eating aura triggers, nested one level under "Refreshment" on Wrath. Forever reworked food, so most foods share one "Well Fed" aura per stat. Feasts only place an object, so their buff is not in the data: Wrath's is named "Well Fed" and the name fallback catches it, and MoP's banquet text reads the buff from its dishes' own auras (`104273`, `104274`), which the table already lists. MoP has no rune, oil or stone. Alchemist's Flask (`105617`) is a script picking one of `79638`–`79640` by highest stat; its text reads the length from `79639`. Elixirs are not tracked on any client. The classic flask tables carry no `spellNames`: every ID comes from DB2, and the name fallback would cost a lookup per name on every refresh with no flask up. A weapon group in `stones` lists its stones best first: the best enabled one in the bags is shown, else the best enabled one (Forever's Elemental Sharpening Stone fits both groups).

**One temporary enchant per hand (Era, TBC, Wrath).** These clients have no `C_Item.GetWeaponEnchantInfo`; `getWeaponEnchant` reads `private.compat.GetTemporaryEnchantmentInfo(slot).enchantID`, as on MoP, for imbues and poisons alike. Because the one enchant may be an oil, a stone, a poison or an imbue, the oil and stone categories list their `enchants` (from each item's use spell, effect 54), and only those count as theirs. Oils and stones last 30 minutes there (base points 1799); poisons 30 minutes on Era, an hour on TBC and Wrath (their spell text; the effect carries no duration). On TBC and Wrath a Rockbiter cast is a dummy that picks one of three enchants per rank by weapon speed, so `IMBUES` lists all three per rank (SpellItemEnchantment names them "Rockbiter <rank>"). Pinned by `tests/imbue_check.lua` T1/T2.

**Weapon imbues on MoP Classic:** MoP has no `C_Item.GetWeaponEnchantInfo`, and a hand there carries one temporary enchant, so `getWeaponEnchant` falls back to `private.compat.GetTemporaryEnchantmentInfo(slot).enchantID`. Flametongue, Frostbrand and Windfury put the enchant of Forever's rank 1 there; Rockbiter puts `3021` (listed as an extra first rank of the same spell) and Earthliving `3345` has its own row.

**Rogue poisons on MoP Classic (`detection = "spell_aura"`):** auras on the rogue, not weapon enchants (DB2: effect 6, 3600 s, no enchant). `groups` gives one icon for the lethal poison (Deadly, Wound) and one for the non-lethal (Crippling, Mind-numbing, Leeching, Paralytic): active while any of the group's auras is up; missing, a click casts the group's remembered spell (`poison_aura_last[group]`), else its first known one. A group with nothing known draws no icon. Drawn through `placeAuraIcon`, which `addAuraIcon` shares. Pinned by `tests/imbue_check.lua` M1/M2.

**Weapon imbues (`imbue`, WoW Forever):** a Forever imbue (Rockbiter, Flametongue, Frostbrand, Windfury) has no aura, only the enchant it puts on the weapon, and Forever has no Cooldown Manager data for Shaman. `GetTemporaryEnchantmentInfo` returns nil for an imbue there (a client, 2026-09-25: `nil` for a main hand carrying Flametongue and Rockbiter), and so does Blizzard's AuraContainer `AddItemEnchantment`, which reads it. So `getWeaponEnchant(slot, IMBUE_BY_ENCHANT)` reads Forever's own `C_Item.GetWeaponEnchantInfo(Enum.WeaponSlot)`, the weapon's enchants as a list (an empty entry, enchant 0, sits beside a real one), and takes the entry whose enchant ID is in `IMBUE_BY_ENCHANT`, whatever its `enchantType` (Forever's own `BuffFrameMixin:UpdateTemporaryEnchantmentBuffs` lists every entry the same way): `IMBUES` lists every rank as `{ spell, enchant }` (DB2 effect 360, `EffectMiscValue_0`; the client confirmed 5 = Flametongue rank 1 and 1 = Rockbiter rank 3, type 3 = Imbue). The function exists only on Forever, so it is checked for presence, as `private.Pixel` does for Forever's pixel rounding; retail has no imbue. An ID the client lacks is never known or reported, so the category is empty on retail and for any character who knows no imbue (`IsPlayerSpell`). Oils and stones are untouched and read the old call, so a weapon carrying an oil and an imbue shows both.
- Active: the applied rank's spell icon; a click casts the highest known rank of that imbue (secure `type = "spell"`, by spell ID). The slot remembers it in `imbue_last[slot]` (rank-1 spell ID).
- Missing: the remembered imbue's highest known rank, else the first known imbue in table order; a stale key falls through.
- Swipe: the call gives only the time left, so the length is snapshotted as the AuraContainer does (`ShouldReassignForEnchantmentInfo`): the time left when first seen, reset when the enchant ID changes or the time left goes up. Oils and stones keep a flat 2 hours (30 minutes on every classic client).
- `SPELLS_CHANGED` refreshes, so a newly learned imbue shows without a reload. The tooltip shows the spell (`icon.spellId`), and a combat reveal (`revealExpired`) swaps the icon to the spell a click casts.
- `DebugDetection` prints the imbue per weapon: spell, enchant ID and time left.
- **Unverified:** the build on `GetWeaponEnchantInfo` has not run in a client yet, and neither has whether the old call reports an oil or a rogue poison on Forever.

**Weapon poisons (`poison`, WoW Forever):** a Forever poison is a vanilla bag item (Instant, Deadly, Crippling, Mind-numbing, Wound; rogue only, `AllowableClass` 8). Using it casts a spell whose effect 360, the imbues' effect, puts an enchant on the weapon (`EffectMiscValue_0`), so it is read the same way: `getWeaponEnchant(slot, POISON_BY_ENCHANT)`. `POISONS` lists every rank as `{ item, enchant }` (DB2 `ItemXItemEffect` → `ItemEffect.SpellID` → `SpellEffect`, build 1.60.1.70124, identical on 70009). Every rank's enchant lasts 30 minutes (`SpellItemEnchantment.Duration` 1800), so the swipe is `max(1800, time left)` and needs no snapshot; imbues keep theirs. Sharing it would not work: the imbue branch clears its slot's snapshot on every refresh that finds no imbue, which is every refresh on a rogue. The category is skipped outright on retail and for anyone but a rogue: retail poisons are auras (MoP's take the `spell_aura` path), and anywhere else the missing-state bag scan would run every rank per refresh for an icon nobody can use, reminding a non-rogue carrying traded poisons of one (review 2026-09-30). It is also empty for a rogue who carries no poison.
- Active: the applied rank's item icon; a click uses the best rank in the bags of that poison (none carried: shown, no click). The slot remembers it in `poison_last[slot]` (rank-1 item ID).
- Missing: the remembered poison's best rank in the bags, else the first poison carried, in table order; a stale key falls through. Nothing carried and nothing applied: no icon.
- Click: secure `type = "item"` plus `target-slot = slot`. The item's spell waits for an item target, and SecureTemplates' `OnActionButtonPress` then calls `UseInventoryItem(target-slot)` on it (`SpellCanTargetItem()`), so the poison lands on that weapon without a targeting cursor. `setSecureAttributes` writes `target-slot` on every call, so a pooled button that takes an oil or an imbue next drops it.
- A combat reveal swaps the icon to the item a click uses. It refreshes on the imbues' events plus `BAG_UPDATE_DELAYED` for the count. `DebugDetection` prints the poison per weapon: item, enchant ID and time left.
- Not tracked: Numbing and Atrophic Poison (items `217346`/`217347`, Season of Discovery runes, effect 54). They are in Forever's DB2 but not known to be obtainable.
- **Unverified:** nothing here has run in a client. The enchant type is inferred to be Imbue (3) from the shared effect 360; the read does not depend on it.

**Duration display:** Aura-based buffs use `SetCooldownFromDurationObject` (secret-safe duration handling). Weapon enchants use `SetCooldown` with the enchant expiration time.

**Suppression (`isSuppressed`):** the tracker hides wherever its aura reads would lie, since a secret flask, food or rune aura reads as nil and would show as missing. Three cases: an active Mythic+ key unless `show_in_challenge_mode` (whose tooltip accepts unreliable detection), raid combat, and **out of combat while `C_Secrets.ShouldAurasBeSecret()`** — dead mid-encounter, or rezzed before the next pull. Before 2026-09-23 that third case read every flask and food as missing (user report, while dead). A hidden container runs no `OnUpdate`, so `Refresh` queues itself on `Util.RunWhenSecrecyClears` for that case; M+ has `CHALLENGE_MODE_COMPLETED` and raid combat keeps the container shown at alpha 0.

**Size:** `GetComponentSize` returns the size `applyLayout` last set (`layoutW`/`layoutH`), not `container:GetSize()`: the layout pass places a `position_reference` follower of this tracker right after re-anchoring it, when the frame's own size reads back stale (`Core/Anchoring.md`). RaidBuffTracker follows this tracker by default.

**Dual wield support:** Weapon enchant categories (oil, weapon buff) display per-slot icons when the player is dual wielding, one for main hand and one for off hand.

**Hide When Applied:** out of combat an active buff's icon is `Hide()`n and takes no slot. **From the pull the layout is pinned** (`pinnedLayout`, set in `OnEnterCombat` before the lockdown, cleared in `OnLeaveCombat` and in `OnDisable` outside its combat guard): every icon takes the slot it would have with all of them shown, an applied one is shown at alpha 0 in its own slot, and the container is sized for the full set (user decision 2026-09-22). A secure button cannot move or show in combat, so this is the only way one can appear mid-fight without overlapping another. Flask, food and rune auras cannot be read in combat, so the expiry is predicted: every `addAuraIcon` / `addWeaponEnchantIcons` records `iconExpiresAt` (nil when not active, or when the remaining time is secret), and the 0.1 s `onUpdate` reveals an applied icon in its slot once that time passes — the "missing" look and pulse, alpha from the container. An aura icon swaps to the bag item a click uses (`addAuraIcon`'s missing branch), since the active one shows the aura's texture; a weapon enchant icon already shows its stone or oil. Never while suppressed or unpinned. Limits: a buff re-applied mid-fight still reappears at its old expiry, and a `/reload` in combat pins nothing until the next pull. Before 2026-09-21 the icon was parked at alpha 0 under the first visible icon, where it could take that icon's click or tooltip, and a re-shown one overlapped it.

**Fonts:** `Refresh` returns early in combat and applies fonts only while shown, and the combat-exit layout pass carries no font pass, so a font request it cannot apply is kept on a `fontsOwed` latch and applied by the next `Refresh` that draws the icons. `RaidBuffTracker` does the same.

**Missing buff glow:** When a tracked buff is not active, the icon is desaturated and shows a glow border. The glow hides automatically when the buff is applied.

**Hover tooltip:** `private.Tooltip.Apply` (`kind = "own"`, `isSecureClick = true`) drives `SetSpellByID(icon.spellId)` for an imbue, else `SetItemByID(icon.itemId)`; `setSecureAttributes` writes both fields on every call, so a pooled button never keeps another category's identity; `tooltip_mode` default `off`. The secure-click flag means `EnableMouse` is owned by `Tooltip.RefreshAll` (formula: clickable=true wins; otherwise tooltip_mode + combat).
