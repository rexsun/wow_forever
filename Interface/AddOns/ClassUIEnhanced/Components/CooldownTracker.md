# CooldownTracker

Renders essential cooldown spell icons via the shared plain-frame icon tracker factory (`private.IconTracker.CreateTracker`, `Core/IconTracker.lua`) inside the container `CUE_CT_Container`. The factory owns all shared tracker machinery — button pool, merged CDM+custom spell map, per-button content refresh, grid layout, watchers, fonts, tooltips, visibility modes, size estimate (see `Core/README.md` and the factory file header). This file documents only the CooldownTracker-specific layers plugged in through `config.hooks`: the **override-bar mode** and the **routed addon icons**.

Defaults: 450×150, icon_size 50. Free-moving root by default; all other components chain from it.

## Factory configuration

`CreateTracker` is called at the bottom of the file; it returns the component table (assigned to `private.CooldownTracker`, registered with ComponentManager) plus the factory context `ctx` (`GetContainer` / `SetContainerSize` / `activeButtons` / `SetButtonAlpha`) that the override layer uses. The takeover parks base icons through `ctx.SetButtonAlpha`, not `button:SetAlpha` — an engine-shown cue on a slot button is not in the icon's alpha chain, so the factory has to park its per-icon aura wrapper alongside.

- `categoryId = CooldownEssential`, `routeKey = "Essential"` — CDM category `CooldownEssential` is a **data source only**: the factory's spell map comes from `CDMDataSource.BuildComponentSpellMaps` (CDM spells minus Additional-Frame-routed ones, plus custom spells) and the Blizzard `EssentialCooldownViewer` frame is alpha-suppressed and never rendered.
- `extraWatcherEvents = { "ACTION_USABLE_CHANGED" }` — the factory's swipe watcher additionally fires on usability changes so the override layer's usability tint stays current.
- `hooks` — the override-bar layer, below.

## Override bar mode (skyriding / vehicle / override)

When a matching action bar is active (`getActiveOverrideInfo`, priority: vehicle > override > skyriding, matching Blizzard precedence; skyriding = bonus bar index 11 at offset 5, filtered to the static `SKYRIDING_ABILITIES` set), the factory's pooled grid is replaced by addon-owned override icons scanned from the bar's action slots. Override frames live in the index-keyed `overrideFrames` pool (`getOrCreateOverrideFrame`: plain Frame parented to the factory container at frame level +2, with square-masked `Icon`, `Cooldown` swipe, `Keybind`, and `ChargeCount` regions).

`applyOverrideLayout` is the full pass (runs in and out of combat): scans slots `(barIndex-1)*12+1 .. +11` — spell actions render by spellID (skyriding bars show only the static ability set), non-spell actions with a texture render texture-only on vehicle/override bars — then lays out a single row aligned per `layout_alignment` (left/center/right within the container width), applies `keybind_font`/`stacks_font` profiles, resolves keybind text from the `ACTIONBUTTON<n>` binding (gated by `show_override_keybind_text`), and sizes the container to `max(totalWidth, min_width) × iconHeight` through `ctx.SetContainerSize` (the factory's `RelayoutSubtree` chokepoint). Entering override mode fires `Anchor.OnComponentStateChange`.

`refreshOverrideContent` is the cheap per-event content-only pass (DurationObject swipe, secret-safe charge text — all-depleted derived from `chargeInfo.isActive` + real non-GCD cooldown, never a `currentCharges` comparison — and usability tint via `C_Spell.IsSpellUsable`); no geometry, no font re-application. Both this pass and `applyOverrideLayout` set `reverse_swipe` **before** the DurationObject, for the reason in `Core/IconTracker.md`.

`exitOverrideMode` hides the override frames directly (no alpha-0 parking), re-enables custom spells, and fires `Anchor.OnComponentStateChange`.

## Routed addon icons (`route_trinkets` / `route_combat_potions`)

When either setting is on, `collectRoutedAddonIcons` (wired as the factory's `getAppendFrames` hook) gathers the source components' icon frames — `TrinketTracker.GetIconFrame(13/14)` and `ConsumableTracker.GetIconsByCategory(1)`, both filtered to `IsShown()` — and returns them for placement at the **end** of the grid, after the spell-sorted pooled buttons. Icons already assigned to an AdditionalFrame are skipped: AF takes priority.

The icons stay parented to their source container and are positioned cross-parent, so the collector sets `SetIgnoreParentAlpha(true)` on each; the factory's `placeIconButton` then owns their rect (`SetPoint`/`SetSize`) and their alpha, and takes an early return past everything keyed off `cue_Icon` — texture, border, desaturation and cooldown text remain the source component's job. The source components read our settings for those via their own `getVisualSettings`, which returns `CooldownTracker.GetSettings()` for any icon `IsIconRoutedHere` reports.

`routedList` (grid order) is the single source of truth: it backs the returned frame list, the public `cooldownTracker.IsIconRoutedHere(icon)` that `TrinketTracker.isSlotRouted` / `ConsumableTracker.isIconRouted` / both `getVisualSettings` query, and the release loop. Each collect **releases everything first and re-adopts** rather than diffing — the set is a handful of icons, and the factory places and re-alphas the result in the same frame, so nothing draws at the restored alpha. Because the icons are not our children, hiding the container does not hide them, so the factory calls the hook with `active = false` (release, adopt nothing) whenever the grid stops owning the screen: component disabled, anchor-chain hidden, or a `preRefresh` takeover such as override mode. `onDisable` releases as well.

`applyAddonIconProperties` re-asserts our `timer_font` (on `DurationText` / `BuffDurationText`), `keybind_font` (resolving keybind text from the trinket's equipped item or the consumable's `itemId`) and `stacks_font` (on `Count`) on every collect — not just on set changes — because the source component keeps applying its own `duration_font` / `keybind_font` / `count_font` on its update pass.

Sizing: the factory adds the routed count to `lastVisibleCount` / the `GetComponentSize` estimate and to `IsCollapsed`, so a grid holding only routed icons still sizes and still counts as non-collapsed.

## Hook wiring

| Hook | Wiring |
|---|---|
| `preRefresh` | Takeover: when enabled and an override bar is active, parks the factory's tracker buttons at alpha 0, disables custom spells (`CustomSpells.OnDisable`), runs `applyOverrideLayout`, returns `true` so the factory's Refresh stops. If the bar *type* changed mid-override, exits the old mode first. When no bar is active, exits override mode (if set) and returns `false` → normal grid pass. |
| `postSwipeUpdate` | In override mode runs `refreshOverrideContent` and returns `true`, suppressing the factory's membership-change Refresh (tracker icons are parked). The factory checks this seam at the **head** of the per-event content pass, before its own re-alpha loop — that loop writes every pooled button's alpha unconditionally, so running it first re-revealed the base icons the takeover had just parked, once per `SPELL_UPDATE_COOLDOWN` (constant while skyriding ability cooldowns tick). |
| `ownsContainer` | `true` while `overrideMode` is set. Suppresses the factory's `SyncAlpha` re-alpha of the pooled buttons — the second writer that would otherwise un-park them, driven from `Anchoring`'s alpha syncs rather than the swipe watcher. |
| `isCollapsed` | In override mode: collapsed = no override frame shown. Otherwise `nil` → factory default (`lastSpellCount == 0`). |
| `getComponentSizeOverride` | In override mode: single-row size from the shown override frames (`icon_size` falling back to 50 when 0, `min_width` floor). Otherwise `nil` → factory grid estimate. |
| `getAppendFrames` | `collectRoutedAddonIcons` — routed trinket/potion icons appended to the end of the grid (above). |
| `getForceVisible` | Installed as `GetForceVisible`; returns `true` while override mode is active so the anchoring system shows the frame regardless of anchor-chain visibility (the user's explicit Hidden still wins). |
| `afterInitialize` | Creates the override watcher: `UPDATE_BONUS_ACTIONBAR` / `UPDATE_OVERRIDE_ACTIONBAR` / `UPDATE_VEHICLE_ACTIONBAR` + player-scoped `UNIT_ENTERED_VEHICLE` / `UNIT_EXITED_VEHICLE` → `Refresh`. Bar-state transitions only; cooldown/usability content updates run through the factory's swipe watcher. |
| `onEnable` / `onDisable` | Re-register / unregister the override watcher events; `onDisable` also exits override mode. |

**`active_glow`** moved onto the same carrier (2026-08-25): the border is created on the aura slot button (`GlowEffect.CreateActiveBorder`, applied by `AuraContainer.ApplyActiveGlow` from `restyleSlotButton`), so the engine shows it exactly while the tracked aura is up. It no longer reads `CDMDataSource.GetAuraState`, so it works with the CDM CVar off and a **custom** spell — which has no viewer child, and therefore never glowed — now glows like any other. Turning it on arms the aura-slot engine, the same as `pandemic_glow`.

**Slot topology.** Slots are allocated on **two** containers, player and target — `SetUnit` is per container, so without the target twin a tracked cooldown whose aura lands on the target (every DoT) got no slot and therefore no cue of any kind. The target container carries Blizzard's own two filter strings (`HARMFUL|PLAYER` on a hostile unit, `HELPFUL|PLAYER|INCLUDE_NAME_PLATE_ONLY` on a friendly one) as two slots per cell, since the container's unit is fixed but the target's friendliness is not. On top of that, a cue in a slot button's subtree cannot inherit per-icon alpha: the button is anchored to its cell, not parented to it. So under `icon_visibility_mode` 2-5 the factory allocates one **pair** of containers per pool index and mirrors each icon's `effectiveAlpha * cue_visAlpha` onto both wrappers, which are the nearest frames we own. Mode 1 (default) keeps the single shared pair, because every container costs a `UNIT_AURA` registration and per-delta bookkeeping for as long as it holds a slot. Details in [../Core/README.md](../Core/README.md).

**`pandemic_glow`** is implemented on Blizzard's native `AddPandemicRegion` (12.1.0.69111): turning it on runs the shared aura-slot engine (`Core/IconTracker.lua`) even with `hide_active_swipe` on, with every drawn part of the bound Cooldown suppressed, so the slot button is a pure carrier for the pandemic region and the icon keeps its own real-cooldown swipe. It works while auras are secret and needs no CDM viewer child, so it no longer holds the keep-alive open. The **target** container is the one that earns it: a refreshable aura is almost always a DoT, while the player container mostly sees long-cooldown burst buffs with no refresh window at all. Costs: the window is Blizzard's and the remaining-% is unreadable, so the urgency-ramp keys (`pandemic_glow_threshold_high`/`_low`, `_color_mid`, `_color_urgent`, `_urgency_borders`) are **gone** — no widget, no reader, the curve renderer behind them deleted, and swept from the profile defaults. The cue is a **static border**: a binary window has nothing to pulse against, and nothing animated can run inside an aura button's subtree, so `pandemic_glow_style` is reduced to the two border variants (outside/inside) and `pandemic_glow_lcg_alpha` is gone too — LibCustomGlow cannot run in that subtree at all. `.context/migration-parity-gaps.md` "Permanently inert settings".
