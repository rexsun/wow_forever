# ConsumableTracker

Standalone. Combat/health/mana potions, healthstones, and utility consumables (drums, combat-res). Category system with `best_only` (health/mana show one icon). Family system (ranks share cooldown); each family stores an `icon` field (`C_Item.GetItemIconByID`) displayed next to its toggle in Options. Mana auto-hides for non-healers; on a talent-tab client (Era, TBC, Wrath), which has no spec role, it always shows. Low health border glow via `C_CurveUtil` secret health handling. Left of CooldownTracker. `GetWantsContentWidth()` → true. `count_font` and `duration_font` profiles with anchor_point/offsets control item count and active buff duration text positioning via `ApplyFontProfile`. Hover tooltip via `private.Tooltip.Apply` (`SetItemByID(itemId)`); `tooltip_mode` default `off`.

**Per game client (#27).** `CONSUMABLE_FAMILIES` is picked at load by `private.ClientScope.CLIENT`: `RETAIL_FAMILIES`, `FOREVER_FAMILIES` (Classic Era too: the same vanilla items under the same IDs), `TBC_FAMILIES`, `WRATH_FAMILIES` or `MISTS_FAMILIES`. One list per client because the items differ and the Options panel lists every family. Every classic ID was read from that client's own DB2 (1.60.1.70245, 1.15.9.70003, 2.5.6.69795, 3.80.2.70177, 5.5.4.70032); TBC and Wrath keep the vanilla families, whose items still drop. On every classic client the Healthstone is a plain item with an item cooldown, so `ITEM_COOLDOWN_SPELL` (retail's charge-spell fallback, `5512 → 6262`) is empty there. Family keys are shared across clients only where the meaning is (`healthstone`), since `tracked_families` lives in the shared profile.

**A cooldown that waits for combat to end (MoP Classic).** MoP's potion category (`SpellCategory` 4) carries flag 4, `COOLDOWN_STARTS_ON_EVENT` (DB2 5.5.4.70032; TBC's carries none): a potion drunk in combat starts its cooldown when combat ends, and until then the item read reports it not enabled. `getItemCooldown` returns that as unusable, so the icon greys out with no sweep, as the in-combat retail healthstone does, and `BAG_UPDATE_COOLDOWN` brings the sweep when it starts.

Defaults: icon_size 40.

**Bag changes:** `BAG_UPDATE_DELAYED` (once per batch; `BAG_UPDATE` fires once per bag) rescans the bags and redraws the icons, then relayouts — `Anchor.Refresh` plus the Additional Frame pass — only when the ordered set of shown families changed. A count dropping from 20 to 19 moves nothing. Every `BAG_UPDATE` used to run both: 757 full passes in two minutes of one `/cueperf` capture.

**Cooldown sweep:** every writer goes through `applyIconCooldown` (`Util.SetIconCooldown`, shared with TrinketTracker), which caches the applied `start`/`duration` on the icon and no-ops when unchanged. Re-issuing `SetCooldown` restarts the engine countdown, and the layout path runs on every layout pass. A DurationObject (the Healthstone charge shape) is a fresh object per query, so the helper compares its `GetStartTime()`: a Healthstone's next charge starts recharging with no off-cooldown moment in between, and a latch on the state alone left that recharge with no sweep. While its values are secret (`HasSecretValues()`, never secret) it is applied on entering the state only. The 0.2s tick offers the sweep on every tick while on cooldown, not only on entering it, for the same reason.

**Fonts:** a font edit made while hidden waits on a `fontsOwed` latch for the next shown `Refresh`, as in `TrinketTracker.md`.

**Free-moving Frame Point:** `syncFramePointToAlignment` keeps the alignment edge fixed by re-deriving `frame_point` from `layout_alignment` (not in `block` layout). A hand-picked Frame Point (`anchor_profile.frame_point_manual`) wins; an Edit Mode drag clears the mark.

**Pool system:** Icons are keyed by familyKey (stable mapping) in `consumableIcons` table with a separate `orderedIcons` array for layout iteration.

**Additional frame routing:** Consumable categories (combat=1, health=2, mana=3, healthstone=4, utility=5) can be assigned to additional frames via the spell dropdown (source key `"Consumable"`, id = category ID). Same cross-parent positioning pattern as TrinketTracker. `GetIconsByCategory(categoryID)` returns all active icons for a category. `GetCategoryIDs()` exposes the category string→ID mapping for the dropdown UI. When disabled but has routed icons, the container stays shown at alpha 0 so OnUpdate keeps running. Notifies AF via `OnAddonIconRefresh()` after each full `Refresh()` and after a `BAG_UPDATE_DELAYED` that changed the set of shown icons — without the latter, a routed icon that becomes active via a bag change (e.g. a non-warlock looting a Healthstone from a Soulwell mid-session) is shown but never positioned by its AF until the next combat edge or options change.

**Primary-stat potion tracker (removed):** A ref-counted `RequestPotionTracking` / `ReleasePotionTracking` API kept `BAG_UPDATE_COOLDOWN` registered while ConsumableTracker was disabled, stamping a 30s expiry per primary-stat potion so `GetActivePrimaryPotionInt()` could feed PrimaryResources' `snapshotPlayerIntellect` baseline. That baseline was the Ebon Might ratio heuristic, which is gone (see `PrimaryResources.md`), and PrimaryResources was the only requester — so the item table, the expiry map, the seeding pass and the soft-enable API are all deleted.
